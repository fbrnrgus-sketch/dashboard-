# 두 손 모아 — 중보기도를 나누는 곳 (초안)

교회 성도들이 기도 제목을 나누고 함께 기도하는 웹앱의 **초안**입니다.
서버 없이 정적 파일만으로 동작하며, 글·댓글·기도 수는 브라우저 `localStorage`에 저장됩니다.

- 주소: https://fbrnrgus-sketch.github.io/dashboard-/prayer-draft/
- 공개 범위: **누구나 들어올 수 있는 공개 사이트** (검색엔진 노출 허용)
- 저장 범위(초안): **올린 사람의 기기·브라우저 한 곳에만** 저장. 다른 사람에게는 아직 보이지 않습니다. 화면 맨 위 얇은 띠가 이 사실을 안내하며, 서버를 연결하면 그 띠만 지우면 됩니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 화면 뼈대 (목록 · 글 하나 · 글쓰기 · 관리자) |
| `styles.css` | '새벽빛' 디자인 (남색→살구빛 배경, 흰 카드, 금빛 포인트) |
| `config.js` | 관리자 비밀번호, 보관 일수, 신고 기준, 분류 목록 |
| `store.js` | **데이터 계층** — 저장·조회 함수만 모아 둔 파일 (서버 전환 시 이 파일만 교체) |
| `app.js` | 화면 그리기, 입력 처리, 음성 입력, 길 찾기 |

## 기능 체크리스트

- [x] 기도 제목 목록 (최신순) · 카드형 · 분류 탭(전체·건강·가정·일터·감사·기타)
- [x] 글쓰기 — 제목 · 내용 · 분류 · **이름 공개 토글(기본 익명)**
- [x] **익명은 진짜 익명** — 토글을 끄면 이름을 저장하지 않음 (본인 확인용 기기 식별자만 별도 보관)
- [x] **함께 기도했어요** — 카드와 상세에서 하트 한 번. 같은 기기에서 중복 집계되지 않음
- [x] **나눔(댓글)** — 글 하나에서 읽고 쓰기, 댓글도 익명/이름 공개 선택
- [x] **응답됨 표시** — 글쓴이·관리자만. 목록에서 살짝 톤 다운 + 배지
- [x] **자동 정리** — 30일(`ARCHIVE_DAYS`) 지난 글은 기본 목록에서 내리고 '지난 기도제목'에서 볼 수 있음 (글은 남김)
- [x] **신고 + 자동 가림** — 한 기기당 1회 집계, 3회(`REPORT_HIDE_THRESHOLD`) 쌓이면 자동 가림
- [x] **관리자 모드** — 하단 '관리자' 또는 주소 끝 `#admin`, `ADMIN_PIN` 입력 → 신고 목록 확인, 가리기·복구·삭제
- [x] **삭제 권한** — 글쓴이 본인 + 관리자 (두 번 눌러 확인)
- [x] **음성 입력** — 글쓰기 마이크 버튼(Web Speech API, `ko-KR`). 미지원 브라우저·권한 거부·오류 안내 포함
- [x] **위기 상황 안내** — 자해·극단적 선택 관련 표현이 감지되면 게시 전에 상담전화 109 안내 (차단하지 않음)
- [x] **반응형** — 320px 모바일 ~ 데스크톱(최대 720px 가운데 정렬)
- [x] **검색 노출** — title/description/OG 메타태그
- [x] 첫 실행 샘플 기도제목 5건 (모두 가상 이름 · 연락처 없음)

## 설정 바꾸기 (`config.js`)

```
window.DSM_CONFIG = {
  SITE_NAME: '두 손 모아',
  ADMIN_PIN: '9999',        // 관리자 비밀번호 — 배포 전에 반드시 바꾸세요
  ARCHIVE_DAYS: 30,          // 지난 기도제목으로 넘어가는 날수
  REPORT_HIDE_THRESHOLD: 3,  // 자동 가림 신고 횟수
  CATEGORIES: [ ... ]
};
```

분류를 바꾸면 목록 탭·글쓰기 선택지가 함께 바뀝니다. 이미 올린 글의 분류 값이 목록에 없으면 '기타'로 표시됩니다.

## 로컬에서 열어 보기

```
cd prayer-draft
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

음성 입력은 `https` 또는 `localhost`에서만 동작합니다. 파일을 더블클릭해 `file://`로 열면 음성 입력은 꺼지고 나머지는 그대로 동작합니다.

## 데이터 초기화 (초안 확인용)

브라우저 개발자 도구 콘솔에서:

```
await DSMStore.resetAll();   // 샘플 상태로 되돌리기
localStorage.removeItem('dsm_posts_v1');  // 완전히 비우기
```

## 알려진 한계 (초안이므로)

1. **이 기기에만 저장됩니다.** 성도들끼리 글이 보이려면 서버(Supabase 등)가 필요합니다.
2. **관리자 비밀번호는 소스에서 보입니다.** `#admin` 화면은 실수 방지용 '가림'이며 진짜 잠금이 아닙니다. 실제 운영에서는 서버 인증으로 바꿔야 합니다.
3. **음성 입력은 브라우저 지원에 달려 있습니다.** Chrome·Edge·삼성 인터넷(안드로이드)에서는 잘 되고, 사파리·파이어폭스에서는 버튼이 숨거나 안내 문구가 나옵니다.
4. **위기 안내는 안내만 합니다.** 글을 막지 않으며, 표현을 놓칠 수 있습니다.
5. **공개 사이트입니다.** 누구나 글을 쓸 수 있으므로, 운영 전에 신고·가림 절차와 게시 규칙 한 줄을 정해 두는 것이 좋습니다. (연락처·주소 같은 개인정보는 적지 않도록 안내 권장)

## 다음 단계 — 서버 연결하기

`store.js`의 함수 구현만 Supabase 호출로 바꾸면 `app.js`는 그대로 씁니다.

필요한 것: Supabase 프로젝트 1개(무료 등급), 테이블 3개(`posts`, `comments`, `prays`), 그리고 아래 함수들을 같은 이름·같은 인자로 구현.

| 함수 | 서버에서 할 일 |
| --- | --- |
| `listPosts({category, archived})` | `posts` 조회 + `prays` 개수 집계 |
| `addPost(data)` | `posts` insert (익명이면 `author_name`을 `null`로) |
| `togglePray(id)` | `prays` insert/delete (`post_id` + 기기 식별자 unique) |
| `addComment(id, data)` | `comments` insert |
| `markAnswered(id, bool)` | `posts.answered` update |
| `reportPost(id, reason)` | `reports` insert 후 3회 이상이면 `hidden = true` |
| `deletePost(id)` | `posts` delete (권한은 RLS에서 확인) |

권한은 반드시 서버(RLS)에서 확인해야 합니다. 초안에서 화면이 버튼을 숨기는 것은 보호가 아닙니다.
